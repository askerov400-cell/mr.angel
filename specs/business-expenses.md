# Расходы и прибыль X2POS — 12.10.2026

Получать /payments?operation=credit последовательно до пустой страницы, фильтр
branch_id, date_start/date_end, per_page=500. Фактический ответ: payments=list,
date_of_payment UTC без зоны, amount отрицательный. Нормализовать расход в
положительное число; неожиданная схема/знак/дубли/чужой филиал/дата/429 не дают
частичного итога. Отменённые/удалённые платежи исключать по подтверждённому
is_deleted; неоднозначные возвращённые/долговые выплаты не считать расходами.

Выплаты, связанные с order_id/procurement_id/source_account_id, исключать из
расходов прибыли: возвраты в выручке, закупки в себестоимости, переводы денег.
Категории расходов — явный список X2POS_EXPENSE_CATEGORY_IDS; неизвестные
категории сохранять отдельной суммой/count и не считать прибыль за такие дни.
Без notes, контрагентов, сотрудников и исходных платежей в базе/модели.
Проверенная текущая выборка: 2 аренда, 5 зарплата, 6 налоги, 8 прочие,
268/269 комиссии (доставка/оплата). Названия из notes не сохранять; показывать
идентификаторы категорий. Справочника API нет. Настройки содержат только ID.

Общий цикл: полная выборка продаж, затем полная выборка расходов за 90 дней;
сохранять атомарно после успеха обоих списков. Общий lock не допускает
конкурирующих запросов процесса. Ошибка расходов сохраняет предыдущий снимок
продаж и расходов; признак устаревания остаётся.

Дневные агрегаты: расходы/count, исключённые выплаты/count, неизвестные
выплаты/count, расходы по category_id. История при изменении агрегата.
Расчётная прибыль отдельно FIFO и средняя = total - cost - expenses_total,
только при полноте обеих выборок и отсутствии неопределённых выплат.
До подтверждения полноты учёта пользователем не называть расчёт окончательной
чистой прибылью; показывать «расчётная прибыль по данным X2POS».
X2POS_EXPENSES_COMPLETE=1 только после явного подтверждения всех расходов.
X2POS_PROFIT_METHOD FIFO/average определяет основной показатель, до выбора
показывать оба. Налоги учитываются только если записаны; инвестиции/кредиты/
дивиденды не операционные расходы, новые категории требуют классификации.

Добавить показатели в ежедневную сводку, диалог и существующий календарный
отчёт без новых кнопок и ограничений периода. Даты будущего не прогноз.
Старые сохранённые дни без расходов — неизвестно, не 0. RLS/grants прежние,
RPC канонизирует новые агрегаты и проверяет знаки/суммы/категории.

Проверки: страницы/знаки/связи/пустые дни/неизвестные категории/возвраты,
обе формулы, суммирование периода, ошибка без частичной записи, безопасный
RPC, реальная выборка + сверка сумм, весь регрессионный набор, deployment.

Владелец подтвердил: все расходы записаны в X2POS, нужны оба расчёта.
Настройка production X2POS_EXPENSES_COMPLETE=1, без выбора одного метода.


## 12.10.2026 — расходы и чистая прибыль
Владелец подтвердил: все расходы бизнеса записаны в X2POS; нужны оба расчёта.
Спецификация specs/business-expenses.md. Новый x2pos/expenses.py читает
/payments operation=credit последовательно до пустой страницы. Текущие
подтверждённые категории 2,5,6,8,268,269 в X2POS_EXPENSE_CATEGORY_IDS.
X2POS_EXPENSES_COMPLETE=1 в production. Неизвестные/неоднозначные выплаты
отдельно; прибыль при них неизвестна. Выплаты, связанные с чеками/закупками/
переводами, исключаются из операционных расходов во избежание двойного счёта.
Расходы считаются по date_of_payment (UTC -> UTC+5), кредит отрицательный,
в агрегате нормализован положительно. В базе только суммы, counts, category_id;
notes, контрагенты и исходные документы не сохраняются и не передаются модели.
Прибыль FIFO/средняя = total с возвратами - соответствующая себестоимость -
expenses_total. Это прибыль по данным X2POS с расходами по дате выплаты.
Показатели подключены в календарный отчёт, сводку и обычный бизнес-диалог.
Синхронизация продаж и расходов атомарная после обеих полных выборок.
db/business_expenses.sql заменяет server-only INVOKER business_save;
миграция business_expenses успешно применена. RLS и закрытые grants проверены.
