# Утренняя сводка Kaspi — 16.11.2026

## Цель

Ежедневная сводка Kaspi по продажам в 09:05 Asia/Qyzylorda за вчера, по аналогии
с утренним отчётом X2POS. Владелец подтвердил: Kaspi API работает, продажи видны.

## Требования и ожидаемое поведение

- Фоновая задача в процессе бота (Railway) раз в 5 минут; отправляет сводку один
  раз в день после 09:05 (включительно) за предыдущий местный день.
- Сводка — существующая `kaspi/statistics.py`, параметризованная по дню: количество
  по статусам и сумма только завершённых заказов, созданных в выбранный день.
  Сумма не называется прибылью.
- Защита от повторов: дата последней отправки хранится в `user_states` под ключом
  `kaspi_morning`. Отметка пишется до отправки; неизвестный исход доставки не
  порождает повторную рассылку. Повторный запуск в тот же день не дублирует.
- При ошибке Kaspi или сбое записи отметки сводка не отправляется и не помечается.
- Запускается только при заданных KASPI_API_TOKEN и KASPI_OWNER_ID и backend Supabase.
- Доступ только владельцу KASPI_OWNER_ID; данные покупателей не сохраняются и не
  передаются модели.

## Границы

- Не считается прибыль, себестоимость или комиссии.
- Лимит 100 заказов на раздел сохраняется; при достижении выборка помечается неполной.

## Данные и безопасность

- Используется существующая таблица `user_states` и RPC `save_user_state`; новых
  таблиц и миграций нет. Значение — ISO-дата последней отправки, без PII и ключей.

## Критерии готовности

- До 09:04 не отправляет; с 09:05 отправляет за вчера один раз.
- Повторный запуск в тот же день не дублирует.
- Ошибка API или отметки не шлёт и не помечает.
- Тесты `tests/test_kaspi_morning.py` проходят; `tests/test_kaspi.py` не сломан.
