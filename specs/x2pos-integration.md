## Уточнения документальной сверки 10.10.2026

- Таймаут 10 секунд задаётся на один сетевой запрос client.request. Составной каталог делает employee/products/stock; обработчик ждёт до 32 секунд. Для проверки подключения ожидание до 12 секунд, для движений до 22. Это фактические ограничения кода; общий предел 10 секунд на всё действие не реализован.
- Интерфейс пишет «Последние 7 дней», но client.movements не передаёт даты и не фильтрует период локально. Период ответа API — **Требует проверки**. По одному тексту интерфейса нельзя объявлять фильтрацию подтверждённой; зависимое изменение кода требует отдельного решения.

### Уточнение после реального чтения API

10.10.2026 GET подтвердил каталог из 50 разновидностей; остатки есть для 10, отсутствие остальных не трактуется как ноль. Приёмки и перемещения читаются. Списания/ревизии содержат документы нескольких филиалов; заголовок Branch-Id и пробный параметр branch_id не ограничивают ответ выбранным филиалом.

Требование завершения: валидировать структуру и действие, локально отбирать только документы выбранного разрешённого филиала. Чужие документы никогда не показывать. Некорректный идентификатор филиала или действие считать ошибкой. Пагинацию определять по исходной странице API, чтобы фильтрация не скрывала последующие страницы. Пустая отфильтрованная страница означает отсутствие документов выбранного филиала только на этой странице.

Убрать неподтверждённые заявления «последние 7 дней» и «даты UTC»: показывать страницу API и даты как в X2POS. Историческое требование периода 7 дней остаётся выше; оно не подтверждено и выделяется в отдельное дальнейшее уточнение API, а не имитируется интерфейсом.

Проверки исправления: смешанная страница не раскрывает чужой филиал; полная страница чужих документов сохраняет переход дальше; неверный филиал/действие вызывает безопасную ошибку; реальное чтение каждого из четырёх видов движений проходит после фильтрации.
