# Память Хранителя в Supabase

Статус: в работе; база создана, подключение приложения ожидает серверного ключа.

## Цель

Хранить данные Хранителя в Supabase, чтобы память не зависела от компьютера и временного диска Railway.

## Первый этап

- Создать проект в выбранной пользователем организации; стоимость подтвердить до создания.
- Создать таблицы `facts`, `observations`, `goals`, `events`, совместимые с текущей SQLite-памятью.
- Каждая запись принадлежит Telegram-пользователю. Его ID брать только из обновления Telegram, а не из текста сообщения или ответа модели.
- Запись подтверждённых фактов остаётся явной через `/remember`; `/memory` и контекст общения читают факты только своего пользователя.
- Сохранить текущую SQLite-базу и JSON-файлы. Перенос данных выполнять отдельно, с проверкой количества записей и без дублей.
- Разместить код хранилища в отдельной папке; оставить совместимость текущих функций доступа к данным.

## Безопасность

- RLS включён на всех таблицах. У `anon` и `authenticated` нет доступа; публичных политик нет.
- Доступ серверного бота через серверный ключ Supabase, только в `.env` и переменных Railway. Плагин для работы с БД не заменяет ключ приложения.
- Фильтрация по `telegram_user_id` обязательна в каждом пользовательском чтении. Серверный ключ обходит RLS; проверка принадлежности выполняется в коде бота.
- Секреты, тексты памяти и персональные данные не выводятся в логи или публичный Git.
- Ошибка Supabase не вызывает незаметный переход на локальную базу. Успех записи сообщается только после подтверждения БД.

## Критерии готовности

- Проект активен; таблицы, ограничения и индексы созданы.
- Проверка безопасности не выявляет доступ к памяти через публичные роли.
- Тестовая запись прочитана; другой пользователь её не получает. Тест не оставляет данные в рабочей памяти.
- Бот подключён к Supabase; `/remember` и `/memory` проверены.
- Проверено поведение при недоступной базе.
- Локальные данные сохранены. Статус переноса отмечен отдельно.

## Вне первого этапа

Автоматическое сохранение всех сообщений, n8n и перенос JSON-памяти без принадлежности пользователю. Эти изменения требуют отдельных спецификаций.
