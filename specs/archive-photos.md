# Архив фото с поиском по подписи — 16.11.2026

## Цель

Владельцу нужно заливать фото (в первую очередь стеллажей) в раздел архива
и быстро находить их по запросу голосом или текстом. Хранение постоянное —
сам файл в Supabase Storage, не по временной ссылке Telegram.

## Требования и ожидаемое поведение

- В любом разделе архива («ТОО автомобиля», «Рецепты еды», «Рабочие фото») при
  выбранном разделе можно отправить фото с подписью (caption). Подпись обязательна:
  без неё бот запрашивает её следующим сообщением (текстом или голосом).
- Файл фото загружается в приватный бакет Supabase Storage `archive-media`
  (public=false, только сервисный ключ). В `user_states` под ключом `archive_photos`
  хранится JSON-список: раздел, путь в Storage, подпись, дата.
- При выдаче фото бот скачивает файл из Storage и отправляет его; ссылка Telegram
  не используется как источник хранения.
- Запрос «покажи фото …», «фото …» или просто «стеллаж» (текстом или распознанной
  речью) ищет фото по совпадению слов в подписи и присылает изображения. Сначала
  ищутся фото, где покрыты все значимые слова; иначе — частичное совпадение.
- Фото-метаданные не попадают в долговременную память: ключ `archive_photos`
  исключается из контекста модели и из суточного профиля.

## Границы

- Не реализуется визуальный поиск по содержимому изображения (дорого, неточно).
- Поиск идёт по подписи, а не по картинке. Подпись задаёт владелец при загрузке.
- Постоянное хранение требует применить SQL-миграцию создания бакета `archive-media`
  в `supabase_migrations/`. До применения бот продолжает работать по ссылке Telegram.

## Данные и безопасность

- Только владелец, личный чат. Данные покупателей не участвуют.
- Значения секретов не записываются; подписи маскируются существующей `redact`.
- Бакет приватный (public=false), без публичных политик; доступ только сервисным ключом.
- Путь в Storage строится с `telegram_user_id` владельца — изоляция по владельцу.

## Критерии готовности

- Фото с подписью сохраняется в выбранный раздел; без подписи бот запрашивает её.
- Запрос по подписи возвращает нужные фото; без совпадений бот отвечает, что не нашёл.
- Файл хранится в Storage; выдача идёт из Storage, а не по file_id.
- `archive_photos` не попадает в `format_memory` и суточный профиль.
- Тесты `tests/test_archive_photos.py` проходят; существующий набор не сломан.
