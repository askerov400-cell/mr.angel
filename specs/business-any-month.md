# Любой месяц X2POS по запросу

90 дней ограничивают только фоновую сверку, не запросы пользователя.
Прямые бизнес-отчёты читать из X2POS за запрошенный период независимо от
сохранённой истории: последовательно все страницы продаж, затем расходов,
себестоимость и обе прибыли. Месяц без года — текущий год; с годом — указанный.
Май распознавать во всех формах. Никакого искусственного предела давности.
Пустая полная выборка — нули, ошибка API — явная ошибка без частичных сумм.
Фоновую историю/RPC последних 90 дней не менять. Произвольные периоды не
писать этим RPC. Исходные документы не сохранять и не передавать модели.
Для свободного анализа явно названного месяца тоже читать этот месяц API.
Сохранять в user_data только текст последнего бизнес-периода для продолжений
в пределах текущего business_until; /clear сбрасывает его вместе с темой.
Новый прямой отчёт задаёт этот период; анализ без нового периода использует его.
Одинаковая обработка текста/распознанного голоса через handle_text.
Проверить старый месяц, любой год, май, обе формулы, ошибку API, авторизацию,
точный обработчик, модельный контекст старого месяца и регрессионный набор.

## 12.10.2026 — любой месяц по запросу в диалоге
Спецификация specs/business-any-month.md. direct_answer больше не зависит от
90-дневного снимка: авторизация store.identity(owner), requested_snapshot
читает expenses.report(start,end) полностью из API. Расходы и обе прибыли
за исторический месяц возвращаются без календаря. День/месяц/год без предела
давности; май/мая/мае исправлены. report_requested принимает продолжения
«теперь за июнь 2025» в активной бизнес-теме. business_period хранится только
в user_data текущей темы и очищается /clear или истечением business_until.
Свободный анализ явно указанного периода/продолжения получает свежую
запрошенную выборку вместо последних 90 дней. Исторические периоды не пишутся
RPC business_save (его ограничение 90 дней предназначено для мониторинга).
