## Требования и сохранённая история

Старые отметки результатов ниже относятся к своим этапам и не подтверждают текущую работоспособность. При неопределённости действует статус «Требует проверки».

Цель: подключить кабинет продавца к Хранителю через официальный API.
/kaspi и отдельная кнопка меню: просмотр заказов по состояниям за 7 дней, страницы по 10; карточка, приём и отмена. Изменение цен не входит в задачу.
Настройки: KASPI_API_TOKEN и KASPI_OWNER_ID на Railway; ключи и ID не входят в Git.
Доступ: только личный чат с владельцем KASPI_OWNER_ID, закрыт при отсутствии настройки. Не передавать ответы Kaspi в LLM, память или журнал; показывать только номер, сумму и статус, без покупателей.
Запросы: фиксированный HTTPS-хост kaspi.kz, запрет перенаправлений, таймаут 20с, максимум ответа 2МБ, проверка JSON; ошибки без содержимого ответа/ключа.
Документация: https://guide.kaspi.kz/partner/ru/shop/api/orders/q3201
Критерии: GET с правильными параметрами, изоляция владельца, ошибки безопасны, пустая страница не означает сбой; тесты и запуск Railway проверены.
Историческая отметка статуса: реализовано; 105 тестов прошли (19 новых). Реальный GET автоматически проверяется при запуске Railway. Реальные приём/отмена не выполнялись на тестовых данных магазина и проверяются владельцем после подтверждения конкретного заказа.

## Приём и отмена
Уточнение пользователя: подключить приём и отмену заказов.
Карточки из проверенного API, данные callback — случайный nonce, не ID заказа.
Перед приёмом: номер, сумма и явная кнопка подтверждения.
Перед отменой: выбор одной из трёх официальных причин, номер и подтверждение.
Nonce привязан к владельцу в user_data, действует 10 минут, одноразовый, пропадает после перезапуска. Максимум 20 карточек и одно подтверждение.
Перед POST заново GET по коду; совпадение ID, кода, суммы и статуса обязательно, иначе новое подтверждение.
Приём допустим только APPROVED_BY_BANK; отмена только APPROVED_BY_BANK/ACCEPTED_BY_MERCHANT. Дополнительные ограничения проверяет Kaspi.
POST без автоматических повторов; при неопределённом ответе просить проверить кабинет, не объявлять успех. Успех только при совпадении ID/кода/целевого статуса ответа.
Настройки и данные пользователя не меняются; заказы не записываются в память/LLM.
Документация:
https://guide.kaspi.kz/partner/ru/shop/api/orders/q3211
https://guide.kaspi.kz/partner/ru/shop/api/orders/q3209
https://guide.kaspi.kz/partner/ru/shop/api/orders/q3202
Тесты: чужой пользователь, устаревшее подтверждение, повторный callback, изменённый статус/сумма, неверное подтверждение API, причина отмены, редактирование запрещённых состояний.

Railway: b9fa9ef, deployment SUCCESS. Telegram startup подтверждён. Реальный GET Kaspi вернул безопасную ошибку KaspiError, доступ пока НЕ подтверждён. Требуется проверка сообщения /kaspi в боте; реальных изменений заказов не выполнял.

## Диагностика отказа API
09.10: пользователь подтвердил появление кнопки, запрос возвращает общую ошибку. Разделить безопасные коды HTTP, таймаут, TLS/сеть, неверный JSON/формат, размер и настройку ключа. Логи содержат только фиксированный код, без URL, текста исключения, токена и ответа. POST по-прежнему не повторяется.

Диагностика ef885e4: Railway SUCCESS, Kaspi network (URLError без TLS/timeout). Уточняем фиксированную категорию DNS/refused/reset/unreachable, без вывода строки исключения.


## Ответ поддержки Kaspi и правки клиента — 20.10.2026

Поддержка сообщила: для API нет ограничений по зарубежным серверам; постоянный исходящий IP не
обязателен; подозрительные User-Agent могут приводить к блокировкам; активность с нашего IP видна,
препятствий для трафика нет.

Следствие: сеть Railway и изменчивый IP — не причина отказов. Риск в заголовках и поведении.
Сделано в kaspi/client.py: браузерный User-Agent (Chrome), заголовки Accept и Accept-Language;
не более одного запроса в секунду (общий троттлинг с блокировкой); для чтения до двух повторов
с паузами 1,5 и 3 секунды только на 429/500/502/503/504, таймаут и разрыв соединения;
POST без автоматических повторов. Тело ответа, ключ и URL в лог по-прежнему не попадают.

Проверки: 211 тестов в проекте, из них 4 новых: браузерные заголовки, повтор GET на 429,
отсутствие повтора POST, пауза между запросами. Публикация: 86bd8d7. Реальный GET подтверждён
владельцем 20.10.2026: заказы открываются, бот видит Kaspi. Приём и отмена на реальных заказах
не выполнялись.
