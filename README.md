# Хранитель

Telegram-бот для общения и записи данных пользователя.

**[Карта проекта: код, настройки и состояние интеграций](PROJECT_MAP.md).**

## Локальный запуск в PowerShell

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
```

Заполнить `TELEGRAM_BOT_TOKEN` и `DEEPSEEK_API_KEY` в локальном `.env`. Не публиковать этот файл.

```powershell
.\.venv\Scripts\python.exe -u bot.py
```

Остановка: `Ctrl+C`.

Рабочий бот на Railway использует Supabase. SQLite остаётся альтернативным локальным режимом. Прежние модули JSON-памяти и состояния не являются текущим хранилищем рабочего бота. Локальные данные исключены из Git.

Supabase подключён в рабочем боте; для настройки другой среды нужны
`SUPABASE_URL`, серверный `SUPABASE_SECRET_KEY` и `MEMORY_BACKEND=supabase`.
Хранить их в локальном `.env` или переменных Railway. Серверный ключ не публиковать.
В коде по умолчанию остаётся SQLite, если MEMORY_BACKEND не задан. Старые JSON-данные автоматически не импортируются.

При `MEMORY_BACKEND=supabase` полезная информация из личной переписки
автоматически классифицируется и сохраняется: факты, цели, события,
предположения и текущие состояния. `/memory` показывает последние записи.
В группах личная память не используется. Старые JSON-файлы не импортированы.

Автоматические повторы с одинаковым нормализованным текстом не записываются
повторно. Перефразировки могут создавать отдельные записи. За один запрос
классификатор извлекает одну запись. Ошибка памяти не прерывает общение.

Правила работы — `AGENTS.md`. Спецификации — `specs/`.
